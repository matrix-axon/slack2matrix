# AGENTS.md

Context for coding agents working on slack2matrix. The README is the user
guide (runbook, config, testing commands), so read it first. This file covers
what the README doesn't: how the code fits together, the rules that must not
break, and the traps already found.

Local deployment notes live in gitignored files, never in this public repo.
Read them if they exist: `prod/NOTES.md` (production server state and next
steps) and `dev/` (test configs).

## What this is

A Go CLI that imports a Slack export into Matrix (Synapse) with full
fidelity: a space, one room per channel, every message, thread, reaction and
file, original timestamps and senders. All of it is end-to-end encrypted, and
**no plaintext copy of message content may ever reach the server**. It acts
as a Synapse appservice so it can send as real users and as ghosts, and set
`origin_server_ts`.

Status: feature-complete, with a full test import that passes on a
disposable Synapse (see "Validation"). It runs on Linux only.

## Build and test

```sh
make build   # -> bin/slack2matrix
make test    # go test ./...
make vet
```

- The Makefile sets everything needed. If you run `go` by hand, reproduce it:
  `GOEXPERIMENT=nojsonv2 GOFLAGS=-tags=goolm` and `GOROOT` unset.
  - With json/v2 (the Go 1.26+ default), mautrix signs Olm one-time keys
    incorrectly, and other devices can't establish sessions. The binary
    refuses to start (`checkCanonicalJSON` in `internal/e2ee`), and
    `TestCanonicalJSONSignsOneTimeKeysCorrectly` guards it.
  - `goolm` is mautrix's pure-Go Olm, so no libolm is needed.
  - Some shells export an old `GOROOT`; unset it.
- SQLite is `mattn/go-sqlite3`, so cgo and a C compiler are required.
- mautrix-go is pinned to a specific pseudo-version in `go.mod`. Its APIs move
  quickly, so don't bump it casually; re-run a full test import if you do.
- Run `gofmt -l cmd internal` before committing, and `go test -race` for
  anything touching the scheduler or uploads.
- Runtime tools: ImageMagick (`magick`), `ffmpeg` and `ffprobe`.

## Code map

```
cmd/slack2matrix/   CLI subcommands (main.go has the command table)
  import.go         setup/import/finalize/keys/crosssign/reset-channel/send-test
  render.go         offline preview of the events a message becomes; uses
                    state_dir/import.db when present to resolve links
  testclient.go     independent decrypting client for verification (login, check, -dump)
  plan.go           export statistics, -missing lists files absent on disk
internal/config/    YAML config, defaults, path resolution (relative to the config file)
internal/slackexport/ export model and reader: per-channel day files merged and
                    sorted by ts; media path mapping (LocalPath/FilePath)
internal/directory/ Slack user -> Matrix identity (mapped real user or ghost); mutex-guarded
internal/convert/   rich_text blocks and mrkdwn -> HTML + plain text; mentions;
                    Slack URL -> matrix.to mapping (MapURL, PermalinkTS)
internal/emoji/     shortcode table (go:embed data.json, generated by gen/)
internal/transform/ one Slack message -> ordered []*Draft (message, media,
                    reaction, membership); cards, unfurls, link previews
internal/media/     prepare files: thumbnails, HEIC/TIFF -> JPEG, video poster/probe
internal/e2ee/      one OlmMachine per sending user; manual Megolm sessions;
                    Olm sharing; key backup upload; key export; cross-signing
internal/matrix/    appservice client wrapper, ghosts, rooms
internal/store/     import.db: rooms, events (pending/sent), media cache,
                    megolm_sessions, key_delivery, members, file_events, kv
internal/importer/  orchestration
  setup.go          ghosts, space, rooms, power levels, push-rule muting
  schedule.go       ImportChannels: concurrency, link waiting, progress
  room.go           per-channel loop, roomRun.message/send, txnID
  prefetch.go       upload-ahead workers and the per-key upload registry
  media.go          encrypt and upload, remote image download
  reconcile.go      resolve 'pending' rows after a crash
  finalize.go       key delivery, unmute, read markers
  reset.go          reset-channel (purge room, forget local state)
scripts/            synapse-up.sh (disposable Synapse), verify-links.py
```

Data flow: `slackexport` reads a channel, then for each message
`transform.Message` produces drafts. `importer` then sends each draft:
`ensureIdentity`, `ensureJoined`, `attachMedia` if needed, `E2EE.Send`, and
records the result in `store`.

## Invariants (don't break these)

- **E2EE only.** Every message and reaction goes through `E2EE.Send`, which
  calls `EncryptMegolmEvent` explicitly, because mautrix's auto-encryption
  skips `m.reaction`. Media is AES-CTR encrypted client-side before upload.
  Thumbnails are made locally, since the server can't thumbnail ciphertext.
- **Never create or replace a real user's cross-signing keys.** Synapse lets
  an appservice do that silently, which would reset the person's identity. For
  real users the only path is `VerifyWithRecoveryKey`; only ghosts get
  generated keys (`e2ee/keys.go: crossSign`).
- **Resume and dedup depend on stable identifiers.** Don't change any of
  these without a migration plan, because existing state (including
  production) relies on them:
  - the `txnID` formula (`room.go`): sha256 of channel, ts, part and sender;
  - draft `Part` numbering within a message;
  - `SourceKey` (`net.slack2matrix.source`), which is embedded in every
    event's encrypted content and is what reconcile and verification match on;
  - `mediaKey` (`slack:<file id>` or `url:<remote url>`).
- Rows are marked `pending` before sending and `sent` with the event ID
  after. `reconcile` decrypts the room's latest 200 events to settle pending
  rows after a crash.
- Megolm sessions are created manually: one per (room, sender, year), with
  no automatic rotation. Keys go to the mapped humans ("recipients") through
  Olm, their server-side backup (refused if the backup isn't trusted, unless
  forced), and an export file.
- Room version 12: room creators have unlimited power and must not appear in
  `power_levels`. The bot creates every room and is left out (`powerLevels`).
- Synapse honours `?ts=` on `/send` and on state `PUT`, but not on
  `createRoom`, `/join` or `/invite`. Joins and leaves are therefore sent as
  timestamped `m.room.member` state `PUT`s.
- Secrets are never stored by the tool or printed: recovery keys and admin
  tokens are read from files or prompted for (`-` means prompt). The
  appservice tokens, `pickle_key` and `crypto.db` (which holds every room key)
  are sensitive. `dev/`, `prod/`, `state/` and `*.db` are gitignored; keep it
  that way.

## Scheduler and upload-ahead (`schedule.go`, `prefetch.go`)

- Every channel runs in its own goroutine. A priority semaphore caps how many
  messages are in flight (`-concurrency`), with the largest channels served
  first.
- A message linking to an earlier message in another channel waits until that
  channel's cursor has passed the target, so the link can be rewritten to the
  Matrix event (`batch.waitFor`).
  - No deadlock: waiters don't hold a slot, and the channel whose next
    message is earliest can always proceed.
  - Late in a full run, many channels wait on one busy channel, so that
    channel's per-message latency sets total time.
- Media uploads run ahead of the senders in `-media-concurrency` workers, up
  to 1,000 messages ahead per channel.
  - A per-key registry ensures each file is uploaded once.
  - A sender needing an unstarted job takes it over inline. A failed prefetch
    is retried inline.
  - Results are cached in the `media` and `media_failures` tables, so resumed
    runs reuse uploads.
- Progress is logged globally every 1,000 messages, plus a heartbeat after a
  quiet minute.

## Slack export quirks already handled

- One channel directory, `trophés`, is Latin-1 encoded on disk, while
  `channels.json` has it in UTF-8. The reader falls back.
- Channel directories can contain macOS `._*.json` AppleDouble files, which
  the reader skips. They can also contain `canvas_in_the_conversation.json`,
  a list of canvas file objects with no `ts`, so it yields no messages.
  Canvases (`canvases.json`) are counted by `plan` but not imported.
- Media mirror layout: `media_dir` plus the file URL without `https://`,
  verbatim. Percent escapes are kept and the `?t=…` query is part of the
  file name. The README has the download script.
- `thread_broadcast` messages carry a `root` copy of the thread root, which is
  not rendered. Tools that scan for links must ignore it.
- Older `reply_broadcast` cards quote a message through `from_url` without
  `is_msg_unfurl`. `Attachment.QuotesMessage()` catches them, so they're
  rendered as quotes, not dropped as unfurls.
- Slack permalinks look like `https://<team>.slack.com/archives/<C…>/p<16 digits>`.
  `p1689090713181639` is ts `1689090713.181639`. Trailing characters can
  follow the digits. `/team/<id or username>` links map to users through
  `Directory.Find`, which never creates a ghost.
- Exports contain only the final text of edited messages, and no reaction
  times. Reactions use their parent's ts.
- Custom emoji become literal `:name:` text. Unfurls are skipped by default;
  link previews can be embedded as MSC4095 (`import.link_previews`). Card and
  `image` block images are re-hosted when `fetch_card_images` is set; dead
  ones become links.

## Validation

1. **Unit tests:** `make test`.
2. **Disposable server:** `scripts/synapse-up.sh` (`POSTGRES=1` for full-size
   runs; `DATA` is wiped). Then follow the README's Testing section:
   `testclient login -setup-recovery` per user, then `import`, `finalize`,
   then the three `testclient check` paths (Olm, backup restore, key export).
   All three must report OK.
3. **Links:** `testclient check … -dump '*'` prints decrypted events as JSON
   lines among its report. Keep the lines starting with `{` and run
   `python3 -I scripts/verify-links.py <export> <state>/import.db <dump.jsonl>`.
   Any `BAD` line is a bug.
4. **Previewing a change** without importing:
   `render -channel X -ts a,b,c` (or `-sample N`).

Last full run (Oct 2026, 43 channels, 690,904 messages, Postgres-backed
Synapse, everything on SSD, `-concurrency 12`, 8 media workers): 4h30m, 0
failures. 700,773 events decrypted on all three key paths. 4,961 message
links resolved to the right event, 0 wrong. A run before upload-ahead, on
RAID, took 10h47m. Disk use for a full test run: about 42 GB for the Synapse
media store, 4 GB for Postgres and 1.5 GB for state.

## Working conventions

- Match the surrounding code: short doc comments that explain *why*, zerolog
  structured logging, `fmt.Errorf("…: %w", err)` wrapping, and no new
  dependencies without need.
- Keep the README in sync when flags, config keys or the runbook change.
  Mapping changes go in the "How Slack content is mapped" table.
- Commits: short imperative subject, with a body explaining the why. The
  owner commits directly to `main`. Commit or push only when asked.
- Large scratch data must not go in `/tmp` (a small tmpfs). Use a real disk.
- Don't use `pkill -f` or `pgrep -f` with a pattern that also matches your
  own shell command line; it kills the shell running it.
- Production imports are long and touch a live server. Never run anything
  against production (import, reset-channel, finalize, crosssign) without the
  owner's explicit go-ahead.
